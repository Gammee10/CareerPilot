# Secrets Layout (ADR-028, ADR-056)

Everything under this directory except this README is **git-ignored**. Never
commit secret values.

## Structure

```
secrets/
  README.md                      <- this file (the only committed file)
  local/                         <- LOCAL DEV ONLY, generated by scripts/dev-secrets.*
    postgres_password.txt        <- PostgreSQL superuser password
    session_signing_key.txt      <- backend session signing key (placeholder in Phase 1)
    resend_api_key.txt           <- Resend credential scoped to auth/email capability
    gemini_api_key.txt           <- Gemini credential scoped to FastAPI AI capability
    LOCAL_ONLY_MARKER.txt        <- warning marker written by the generator
  prod/                          <- PRODUCTION (VM only), populated by
                                    scripts/fetch-vault-secrets.sh from OCI Vault.
                                    Same filenames as local/.
```

## Rules (non-negotiable per ADR-056)

1. Secrets are injected **only** as file-mounted Docker Compose secrets,
   scoped per container (`compose.yaml` → top-level `secrets:` + per-service).
2. Secret values never appear in environment variables, images, source code,
   logs, or git.
3. The public frontend receives no server-side secrets; FastAPI receives only
   the Gemini credential; the worker receives only what its work requires.
4. Production secret values live exclusively in OCI Vault and are retrieved
   only by the approved deployment procedure onto the VM.

## Capability scoping matrix

| Secret                 | postgres | backend | worker | ai | frontend | caddy |
|------------------------|:--------:|:-------:|:------:|:--:|:--------:|:-----:|
| postgres_password      | ✔        | ✔       | ✔      | ✘  | ✘        | ✘     |
| session_signing_key    | ✘        | ✔       | ✘      | ✘  | ✘        | ✘     |
| resend_api_key         | ✘        | ✔       | ✘      | ✘  | ✘        | ✘     |
| gemini_api_key         | ✘        | ✘       | ✘      | ✔  | ✘        | ✘     |

Local dev placeholders are clearly marked (`local/LOCAL_ONLY_MARKER.txt`) and
are never valid production credentials.
